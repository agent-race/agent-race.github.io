Insights

This page summarizes the key insights and analyses.

Execution Time and Token Consumption

  • LLM inference usually dominates runtime across all agent frameworks, and inefficient prompt engineering, such as appending full histories and using verbose prompts, exacerbates both latency and cost.
    • Two main causes of token inefficiency: appending unnecessary history to prompts and using verbose prompts.
    • AgentScope and CrewAI frequently use the Web tool for precise results, leading to higher token usage due to long text outputs.
    • AgentScope often writes and executes code to solve problems, which requires returning large code blocks, increasing token usage.
  • Token consumption may vary across frameworks even when executing the same workflow, owing to differences in implementation strategies.
    • Token usage varies significantly across frameworks and datasets, especially in GAIA due to its complexity. AgentScope and CrewAI (ReAct workflow) consume large tokens because they include full memory or context in every LLM call, leading to prompt length growth with more reasoning steps.
    • LlamaIndex and Pydantic mainly incur token overhead from returning detailed tool observations, which becomes costly in tool-heavy GAIA tasks.
    • MoA workflows show differences in coordination efficiency: PydanticAI reduces token usage by selectively invoking sub-agents, while CrewAI's centralized global agent accumulates tokens over multiple sequential LLM calls—an issue that worsens as sub-agent count increases.
  • Parallel invocation reduces overall runtime.
    • PydanticAI achieves shorter total runtime than the sum of individual tool and LLM calls by using parallel execution and asynchronous scheduling, allowing multiple components to run simultaneously and reducing end-to-end latency.

Tool Calling

  • Tool execution efficiency varies widely across frameworks, with search and figure-related tools introducing disproportionately high latency.
    • Tool execution efficiency varies significantly across frameworks, especially for high-latency tools like search and figure loaders.
    • Lightweight tools (e.g., txt_tool, docx_tool) show minimal variance, while medium-latency tools (e.g., pdf_tool, python_tool) exhibit moderate differences due to implementation and I/O strategy.
    • Frameworks like AgentScope suffer from excessive tool processing time, mainly due to inefficient multimedia handling, which becomes critical in tool-heavy or multimodal tasks.
    • LLM inference is generally the main bottleneck, but in complex scenarios, tool execution can dominate, highlighting the need for better tool orchestration and API integration in such frameworks.
  • While increasing the number of tools has minimal effect on execution time, it does have a noticeable impact on LLM token usage.
    • LlamaIndex shows a sharp drop in token usage as more tools are added, because the model struggles to select the correct tool. This reduces the depth of ReAct reasoning and leads to fewer tool calls and lower overall token consumption.
    • Execution failures increase with more tools, as some samples exceed the LLM’s context window, highlighting scalability issues in large tool settings.

RAG

  • While agents usually involve external databases for information retrieval, the database performance is overlooked in several frameworks. Vector database is recommended.
    • RAG workflow performance is heavily affected by embedding and retrieval latency.
    • AgentScope shows high vectorization latency due to using a large embedding model as a separate LLM call during setup.
    • Phidata also suffers from slow vectorization, caused by a two-step process involving a slow csv_tool and a SentenceTransformer model for embedding.

Communication Size

  • Inefficient communication architecture and package design lead to high communication overhead in the multi-agent setting.
    • Centralized frameworks like CrewAI incur high communication costs due to sequential sub-agent coordination, where prompt and message size grow with each interaction.
    • Phidata adds further overhead by duplicating message content and including extra metadata, inflating total communication size.

Accuracy

  • The complete absence of output constraints in LLMs may lead to tool invocation failures, whereas excessively strict output validation can incur substantial token overhead and decrease the response success rate.
    • Frameworks like LlamaIndex are prone to tool invocation failures due to GPT-4o’s inconsistent structured outputs, as they require strict input formats; this leads to lower accuracy in complex datasets like GAIA unless input formats are explicitly enforced.
    • LangChain improves robustness through stricter output validation and auto-retries. While such mechanisms increase robustness against malformed outputs, they may backfire in certain scenarios.
